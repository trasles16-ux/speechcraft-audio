> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

## Research findings (verified this session, 14 Sep 2026)

1. **Piper en_ZA voices are not in `rhasspy/piper-voices`** — that repo has only `en_GB` and `en_US` subdirectories. The URLs hardcoded in `piper_tts_engine.py` (`resolve/v1.0.0/en/en_ZA/...`) return HTTP 404. Carina and Tildar are community-trained SA voices; their real host repo needs to be identified (requires Hugging Face auth or a community source). **Action:** PR #3 ships the registry with a `piper_tts` feature but defers the Piper URLs — the whisper assets are fully populated. PR #4 (feature-toggling) must resolve Piper hosting before wiring the download button.

2. **faster-whisper needs 4 files, not 1** — `WhisperModel("tiny")` loads from a local directory that must contain `model.bin` + `tokenizer.json` + `vocabulary.txt` + `config.json`. The registry uses the multi-file shape for whisper assets. All 8 SHA-256 digests (4 per model size) verified:
   - tiny.en: model.bin=`dcb76c…6e6d1` (75.5 MB), tokenizer.json=`fb7b63…fd0ab` (2.2 MB), vocabulary.txt=`34ce3f…3913` (0.46 MB), config.json=`a73a28…ac8` (2.2 KB)
   - base.en: model.bin=`d01c30…a9a` (145.2 MB), tokenizer.json=`fb7b63…fd0ab` (2.2 MB, same as tiny), vocabulary.txt=`34ce3f…3913` (0.46 MB, same as tiny), config.json=`56a6d8…9a9a` (2.3 KB)

3. **`PREFS_DIR`** is exported from `prefs.py` (Windows: `%APPDATA%/SpeechCraft`, POSIX: `~/.speechcraft`). The feature state file goes to `PREFS_DIR/feature_state.json`.

**Goal:** Give the setup wizard a download layer so that when the user enables a feature that has downloadable assets (Piper TTS voices, faster-whisper models), the wizard downloads them on the spot with a real progress bar, reuses the v1.2.0 SHA-256-verified download machinery from `updater.py`, and records the result in a small on-disk "feature state" file so the app knows which features are ready vs pending.

**Architecture:** A new pure-logic module `feature_manager.py` (no wx, no pedalboard, no whisper, no piper) sits between the wizard and the heavy deps. It:

1. Defines a `FeatureAsset` dataclass — one row in a registry per downloadable thing (`feature`, `asset_name`, `url`, `sha256`, `expected_size_bytes`, `dest_path`).
2. Defines a `FeatureState` dataclass — `{ready: bool, asset_path: str, last_error: str | None, downloaded_at: str}` persisted per asset to `~/.speechcraft/feature_state.json`.
3. Provides `download_asset(asset, dest_dir, progress_cb, cancel_check)` — a thin wrapper around `updater.download_with_progress` + `updater.verify_asset_sha256` that downloads to a `.part` file, verifies SHA-256, atomically renames, and writes the state file on success.
4. Provides `is_ready(feature)` and `ensure_ready(feature, progress_cb, cancel_check)` helpers the wizard (PR #4, feature-toggling) will call.

The wizard UI hooks (a "Download" button per enabled-but-missing feature, a progress panel, cancel semantics) are deferred to **v1.3.0-feature-toggling** — this PR is the pure-logic layer + its tests. This keeps PR #3 small and reviewable and matches the roadmap's "5 small PRs" shape.

**Tech Stack:** Python 3.11, stdlib `urllib.request`, `hashlib`, `hmac`, `json`, `dataclasses`, `pathlib`. Reuse `updater.py` (already pure-logic, no wx) verbatim. No new third-party deps.

## Why this shape

The v1.2.0 `updater.py` already solved the hard parts:

| Capability | Where |
|---|---|
| Stream a URL to disk with a byte-level progress callback | `updater.download_with_progress` |
| Cancel mid-download, delete the `.part`, raise a clean error | `cancel_check` param on `download_with_progress` |
| SHA-256 verify a file against an expected hex digest | `updater.verify_asset_sha256` |
| Atomic rename (`.part` → final) so a crashed download never leaves a half-file | `os.replace` inside `download_with_progress` |

`feature_manager.py` is a *registry + state layer* on top of that: which assets exist, where each one lands, and whether the user already has it. The wizard (PR #4) just calls `feature_manager.ensure_ready("piper_tts", "en.za.carina")` and renders the returned progress state.

The state file lives at `~/.speechcraft/feature_state.json` (same `PREFS_DIR` as `setup.json`, same `prefs.py` helpers). One JSON document, keyed by `(feature, asset_name)`. This is the same "progressive save, one file" pattern the wizard uses for `setup.json` — no SQLite, no new persistence format.

The unified multi-file shape means one code path for all asset types: download each file in `files[]`, verify its SHA, write all to `dest_dir/asset_name/`. The caller gets one progress bar across the whole asset (total = sum of `size_bytes`).

The registry values are *data*, not code. They live in the module next to the functions that consume them so there's a single import (`from feature_manager import FEATURE_ASSETS, ensure_ready`). No separate `assets.json` — the Python literal is grep-able, diff-able, and typed.

**`is_downloadable(asset)`** — returns `True` if no file in the asset has a `TODO_` URL prefix (Piper assets are not yet downloadable; whisper assets are). PR #4's wizard download button checks this before enabling.

### The state file

`~/.speechcraft/feature_state.json`:

```json
{
  "piper_tts/en.za.carina": {
    "ready": true,
    "paths": {
      "model": "C:/Users/trace/.speechcraft/models/piper/en.za.carina.onnx",
      "config": "C:/Users/trace/.speechcraft/models/piper/en.za.carina.onnx.json"
    },
    "downloaded_at": "2026-09-14T20:42:00Z",
    "last_error": null
  },
  "local_transcription/tiny.en": {
    "ready": false,
    "paths": {},
    "downloaded_at": null,
    "last_error": "SHA-256 mismatch — file will be re-downloaded on next attempt"
  }
}
```

Keyed by `f"{feature}/{asset_name}"` so one document holds every feature's state. `ready: true` means every file in the asset is on disk and verified. `ready: false` with a non-null `last_error` tells the wizard why (and the user, on the next run, that a re-download is needed).

### The API

```python
@dataclass(frozen=True)
class FeatureAsset:
    feature: str
    asset_name: str
    description: str

    @property
    def key(self) -> str:
        return f"{self.feature}/{self.asset_name}"


def asset_key(feature: str, asset_name: str) -> str: ...
def list_features() -> tuple[str, ...]: ...
def list_assets(feature: str) -> tuple[str, ...]: ...
def get_asset(feature: str, asset_name: str) -> FeatureAsset: ...

def load_feature_state(*, state_file: Path | None = None) -> dict[str, dict]: ...
def save_feature_state(state: dict[str, dict], *, state_file: Path | None = None) -> None: ...
def is_ready(feature: str, asset_name: str, *, state_file: Path | None = None) -> bool: ...

def download_asset(
    feature: str,
    asset_name: str,
    *,
    dest_dir: Path | None = None,
    progress_cb: Callable[[str, int, int], None] | None = None,
    cancel_check: Callable[[], bool] | None = None,
    state_file: Path | None = None,
) -> dict: ...
"""Download one asset (all its files) into dest_dir. Returns the state
entry dict that was written to feature_state.json. Raises
FeatureDownloadError on network / SHA / cancel.

progress_cb signature: progress_cb(asset_key, bytes_downloaded, total_bytes).
The total for a multi-file asset is the sum of all file sizes so the
caller can drive one progress bar across the whole asset.
"""

def ensure_ready(
    feature: str,
    asset_name: str,
    *,
    dest_dir: Path | None = None,
    progress_cb: ... = None,
    cancel_check: ... = None,
    state_file: Path | None = None,
) -> bool:
    """Return True if the asset is ready (already on disk or just
    downloaded). False on cancel. Raises FeatureDownloadError on
    failure. Idempotent: calling it twice only downloads once."""
```

`dest_dir` defaults to `PREFS_DIR / "models" / <feature>` so a user who uninstalls SpeechCraft but keeps their data folder retains their downloaded voices. The `piper_tts_engine.py` currently points at `./piper_models` (cwd-relative) — **PR #4** will switch the engine to read from the new `dest_dir` so the wizard's downloads are actually used.

```python
Pure logic — no wx, no pedalboard, no whisper, no piper. Reuses the

What this module does:

- Persist per-asset state to ``PREFS_DIR/feature_state.json``
  (ready / not-ready / last error / paths).

What this module does NOT do:
- No GUI. No progress dialog. No auto-download-on-launch.
- No gating of menu items (that's v1.3.0-feature-toggling).

def asset_key(feature: str, asset_name: str) -> str:
    """Stable key used in feature_state.json and progress callbacks."""
    return f"{feature}/{asset_name}"


def list_features() -> tuple[str, ...]:
    return tuple(FEATURE_ASSETS.keys())


def list_assets(feature: str) -> tuple[str, ...]:
    if feature not in FEATURE_ASSETS:
        raise KeyError(f"unknown feature {feature!r}")
    return tuple(FEATURE_ASSETS[feature].keys())


def get_asset(feature: str, asset_name: str) -> FeatureAsset:
    """Return the FeatureAsset for (feature, asset_name), or raise KeyError."""
    try:
        raw = FEATURE_ASSETS[feature][asset_name]
    except KeyError as exc:
        raise KeyError(f"unknown asset {asset_key(feature, asset_name)!r}") from exc
    return FeatureAsset(
        feature=feature,
        asset_name=asset_name,
        description=raw.get("description", ""),
    )


def is_downloadable(feature: str, asset_name: str) -> bool:
    """True if all files in the asset have real (non-TODO) URLs.

    Piper assets ship with placeholder URLs until the SA community
    voice repo is identified — this function gates the wizard's
    Download button so it is disabled for those.
    """
    raw = FEATURE_ASSETS[feature][asset_name]
    return all(not f["url"].startswith("TODO_") for f in raw["files"])


def total_asset_bytes(feature: str, asset_name: str) -> int:
    """Sum of size_bytes across all files in the asset.

    Used to drive a single progress bar spanning the whole download.
    """
    raw = FEATURE_ASSETS[feature][asset_name]
    return sum(f["size_bytes"] for f in raw["files"])
```

```python
#: Where feature_state.json lives. Mirrors setup.json (same PREFS_DIR).
FEATURE_STATE_FILE: Final = PREFS_DIR / "feature_state.json"


def _empty_state() -> dict[str, dict]:
    return {}


def load_feature_state(*, state_file: Path | None = None) -> dict[str, dict]:
    """Return the parsed feature_state.json. Missing file -> empty dict."""
    path = state_file if state_file is not None else FEATURE_STATE_FILE
    if not path.exists():
        return _empty_state()
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
    except (json.JSONDecodeError, OSError):
        # Corrupt / unreadable state is treated as "nothing downloaded
        # yet" — the next download attempt will repopulate it. Never
        # crash the app on a bad state file.
        return _empty_state()
    if not isinstance(data, dict):
        return _empty_state()
    return data


def save_feature_state(state: dict[str, dict], *, state_file: Path | None = None) -> None:
    """Atomically write the state file. Creates PREFS_DIR if needed."""
    path = state_file if state_file is not None else FEATURE_STATE_FILE
    path.parent.mkdir(parents=True, exist_ok=True)
    tmp = path.with_suffix(".json.tmp")
    tmp.write_text(json.dumps(state, indent=2), encoding="utf-8")
    tmp.replace(path)  # atomic on Windows + POSIX


def is_ready(feature: str, asset_name: str, *, state_file: Path | None = None) -> bool:
    """True iff the asset is on disk AND verified. Otherwise False."""
    state = load_feature_state(state_file=state_file)
    entry = state.get(asset_key(feature, asset_name))
    return bool(entry and entry.get("ready"))
```

### Task 4: `FeatureDownloadError` + `download_asset` (single-file shape)

**Objective:** Download one single-file asset (e.g. `local_transcription/tiny.en`) with progress + cancel + SHA-256 verification, and write the state on success.

**Files:**
- Modify: `feature_manager.py` — add `FeatureDownloadError`, `download_asset`

**Step 1: Add the exception + the download path**

```python
class FeatureDownloadError(Exception):
    """Raised when a feature asset download or verification fails.

    Subclasses never carry sensitive data; the message is user-safe
    (the wizard shows it verbatim in a dialog).
    """


def download_asset(
    feature: str,
    asset_name: str,
    *,
    dest_dir: Path | None = None,
    progress_cb: Callable[[str, int, int], None] | None = None,
    cancel_check: Callable[[], bool] | None = None,
    state_file: Path | None = None,
) -> dict:
    """Download + verify one asset into ``dest_dir``; update state file.

    For multi-file assets (piper_tts), all files are downloaded in
    sequence; progress_cb is called with a running total across the
    whole asset so the caller can drive a single progress bar.

    Returns the state entry dict that was written (so the caller can
    show the user where the file landed without re-reading disk).

    Raises FeatureDownloadError on any of: unknown asset, network
    failure, SHA-256 mismatch, cancel requested, or IO error.
    """
    import datetime
    import os

    from updater import (
        UpdateCheckError,
        download_with_progress,
        verify_asset_sha256,
    )

    try:
        raw = FEATURE_ASSETS[feature][asset_name]
    except KeyError:
        raise FeatureDownloadError(
            f"Unknown asset {asset_key(feature, asset_name)!r}"
        ) from None

    base_dir = (dest_dir if dest_dir is not None else (PREFS_DIR / "models" / feature))
    os.makedirs(base_dir, exist_ok=True)

    key = asset_key(feature, asset_name)
    state = load_feature_state(state_file=state_file)

    def _cb(downloaded: int, total: int) -> None:
        if progress_cb is not None:
            progress_cb(key, downloaded, total)

    try:
        if "model_url" in raw:
            # Multi-file: piper-style (model + config)
            paths: dict[str, str] = {}
            offsets: list[tuple[str, int, int]] = []  # (label, offset, size)
            running = 0
            file_plan = [
                ("model", raw["model_url"], raw["model_sha256"], raw["model_size_bytes"]),
                ("config", raw["config_url"], raw["config_sha256"], raw["config_size_bytes"]),
            ]
            for label, url, sha, size in file_plan:
                # Wrap the per-file progress cb so the caller sees one
                # continuous bar across the whole asset.
                offset = running
                def _file_cb(dl: int, total: int, _off: int = offset, _size: int = size) -> None:
                    if progress_cb is not None:
                        progress_cb(key, _off + dl, _size + (total - dl) if total else _size)
                dest = base_dir / f"{asset_name}.{label}"
                download_with_progress(
                    url,
                    str(dest),
                    progress_cb=_file_cb,
                    cancel_check=cancel_check,
                )
                if not verify_asset_sha256(str(dest), sha):
                    os.unlink(dest)
                    raise FeatureDownloadError(
                        f"SHA-256 mismatch for {key} ({label}). "
                        "The file will be re-downloaded on the next attempt."
                    )
                paths[label] = str(dest)
                running += size
            state[key] = {
                "ready": True,
                "paths": paths,
                "downloaded_at": datetime.datetime.now(datetime.timezone.utc).isoformat(),
                "last_error": None,
            }
        else:
            # Single-file: whisper-style
            url = raw["url"]
            sha = raw["sha256"]
            dest = base_dir / f"{asset_name}.bin"
            download_with_progress(url, str(dest), progress_cb=_cb, cancel_check=cancel_check)
            if not verify_asset_sha256(str(dest), sha):
                os.unlink(dest)
                raise FeatureDownloadError(
                    f"SHA-256 mismatch for {key}. The file will be re-downloaded."
                )
            state[key] = {
                "ready": True,
                "paths": {"file": str(dest)},
                "downloaded_at": datetime.datetime.now(datetime.timezone.utc).isoformat(),
                "last_error": None,
            }
    except UpdateCheckError as exc:
        # Network / cancel — record the failure so the wizard can show it
        state[key] = {
            "ready": False,
            "paths": {},
            "downloaded_at": None,
            "last_error": str(exc),
        }
        save_feature_state(state, state_file=state_file)
        raise FeatureDownloadError(str(exc)) from exc

    save_feature_state(state, state_file=state_file)
    return state[key]
```

```python
def ensure_ready(
    feature: str,
    asset_name: str,
    *,
    dest_dir: Path | None = None,
    progress_cb: Callable[[str, int, int], None] | None = None,
    cancel_check: Callable[[], bool] | None = None,
    state_file: Path | None = None,
) -> bool:
    """Idempotent: return True if the asset is ready (already on disk,
    or just downloaded), False if the user cancelled mid-download.
    Raises FeatureDownloadError on network / SHA failure.
    """
    if is_ready(feature, asset_name, state_file=state_file):
        return True
    download_asset(
        feature,
        asset_name,
        dest_dir=dest_dir,
        progress_cb=progress_cb,
        cancel_check=cancel_check,
        state_file=state_file,
    )
    return is_ready(feature, asset_name, state_file=state_file)
```

## Risks / open questions

1. **Hugging Face rate limits / URL stability.** The `resolve/main` URLs are stable but not version-pinned. If the voice files are ever re-uploaded, the SHA-256 in the registry will no longer match and every user will see a "SHA-256 mismatch" on their next download. **Mitigation:** PR #4's download-failure dialog should offer "Report this" (links to the repo issue tracker) and "Force re-verify" (clears the state and retries). For now, the registry ships with the current digests; a future PR adds a "recompute digests" maintenance script.
2. **Multi-file progress math.** The piper asset downloads a model (~78 MB) then a config (~2 KB). The single-progress-bar callback reports the running total across both. The caller needs to know the total up-front to size the bar — `ensure_ready` could expose `total_bytes_for_asset(feature, asset_name)` as a small helper if PR #4 needs it.
3. **State-file locking.** If two SpeechCraft processes run at once (rare, but possible during dev), a simultaneous `save_feature_state` could corrupt the JSON. The atomic `.tmp` rename handles the common case (one writer at a time); a real multi-process lock is out of scope for v1.3.0.
4. **Core build.** `feature_manager.py` imports `updater.py`, which is stdlib-only. The module is safe for the Core build. The *assets themselves* (Piper voices, whisper models) are only useful if the user has the Full build (which bundles `piper` + `faster_whisper`). The wizard should grey out downloads for features the user doesn't have the runtime for — that gating is PR #4's job, not this PR's.
